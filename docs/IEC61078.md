# IEC 61078:2016 in RAPTOR Studio

RAPTOR Studio models reliability block diagrams (RBDs) and evaluates them by
Monte Carlo simulation. IEC 61078:2016 defines RBD logic and qualitative
(minimal tie/cut sets) and quantitative (Boolean, BDD, analytical) methods. It
does **not** define a file format or a simulator, and RAPTOR is not a certified
implementation of the standard.

This page is documentation, not application UI. MCP clients can read it with
`read_doc('iec61078')`.

## Clause coverage

| IEC 61078 topic | Status | In RAPTOR Studio |
| --- | --- | --- |
| 5.2 binary states and an acyclic RBD | Supported | Blocks and the system are up/down; link cycles are refused. Dependency cycles are an extension and are warned about. |
| 7.2–7.4 series, parallel and mixed structures | Supported | Series and parallel templates, plus arbitrary acyclic mixes. |
| 7.5.1 m-out-of-n structures | Supported | A voting node counts up paths; identical and non-identical blocks are supported. |
| 7.5.2 common/repeated blocks | Not implemented | A block has one input and one output link, so the same block cannot appear on two paths. Copying it makes an independent block, not the same component. |
| 7.5.3 composite blocks and standby | Partial | Hot/cold standby and dependencies are simulated directly; there is no single composite-block probability input. |
| 7.6 transfer gates and sub-RBDs | Partial | Hierarchies have one In and one Out marker; multi-port sub-RBDs are not supported. |
| 8, 11 minimal tie/cut sets, Boolean truth tables, Karnaugh maps, BDDs | Not implemented | No qualitative path/cut-set output and no Boolean or BDD solver. |
| 9 constant probability of success/failure | Not implemented | No separate constant-probability calculator; a time-based model is simulated. |
| 10 time-dependent repaired/non-repaired blocks | Supported | Failure/repair distributions are simulated. Availability, mission reliability, failure counts and MTBDE are reported; graphs show sampled A(t). |
| 10.3.2, 10.3.4 analytical average availability, PFDavg, Vesely rate, failure frequency | Not implemented | No analytical integration and no separate conditional failure intensity, unconditional failure intensity or PFDavg output. |
| 12.1 non-coherent RBDs and inverted blocks | Not implemented | Success-path/coherent diagrams only. |
| 12.2 dynamic RBDs, PAND/SEQ, external CCF elements | Not implemented | Dependencies, standby, resources and phases cover some similar situations by simulation, but not PAND/SEQ or a CCF element/β-factor. |
| Annex D importance factors | Estimated | Birnbaum, RAW, RRW and Vesely-Fussell, estimated by re-simulation (one extra batch per block) rather than from analytical derivatives. Opt-in under Run ▸ Analysis ▸ Importance measures; results in the **Importance** tab. Ranked per block only — hierarchies are not yet elements of the analysis. Criticality, diagnostic and DIM are not implemented. |
| Annex E/F Petri-net DRBDs and numerical curves | Not implemented as such | Monte Carlo can represent many of the same dynamic behaviours. |

## Result mapping

This page maps RAPTOR's result fields to the standard. The only measure it
adds beyond Raptor 7's own outputs is the estimated Annex D importance set
(see the formulas page, `read_doc('formulas')`, for the equations). Capacity,
cost and weak-link detail stay on their own tabs.

| RAPTOR result | IEC 61078 reference | Note |
| --- | --- | --- |
| Availability | 10.3.1 / 10.3.2 | Simulated time-average system availability. |
| Reliability | 10.3.3 | Fraction of runs with no system failure over the horizon. |
| System failures | 10.3.4 (input to frequency) | Failure count; failure intensity is not a separate output. |
| MTBDE | Related term, not Clause 10 | Mean time between downing events (IEC 60050-192). |
| MDT | Related term, not Clause 10 | Mean system down time (IEC 60050-192). |
| MTBM | Related term, not Clause 10 | Mean time between maintenance events. |

Not computed: minimal tie/cut sets, Boolean/BDD evaluation, Vesely conditional
failure intensity, unconditional failure intensity, PFDavg, non-coherent
blocks, PAND/SEQ gates, and CCF groups/β. Importance factors are *estimated by
simulation* (Annex D), not derived analytically, and criticality/diagnostic/DIM
are not offered.

- F.2.2: repaired series steady-state availability.
- Figure 8 / 9.4: identical 2-out-of-3 availability.
- 11.8.2 / Figure 39: non-identical 2-out-of-5 availability.

The tests use a fixed seed and an explicit sampling tolerance; they check the
RBD semantics, not certified compliance.

## Using the information

- **GUI:** Results ▸ Final Results ▸ **Importance** shows the estimated
  importance measures for a run that requested them (Run ▸ Analysis ▸
  Importance measures). Definitions live on the formulas page, not in the tab.
- **MCP:** `simulate(..., importance="both")` requests the analysis;
  `get_report(run_id, section="importance")` returns its report section, and
  the `simulate` result carries the structured form. `describe_metrics()` lists
  the metric names; `read_doc('formulas')` has the equations.
- **Not covered:** the analytical solver, minimal cut/tie sets, per-hierarchy
  importance, CCF and dynamic gates are not implemented.
