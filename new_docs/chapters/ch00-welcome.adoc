== Welcome

*Time: about 10 minutes. You need: nothing yet.*

=== What this book is

This book teaches you how to predict when things break — before they do.
You will build small models of real machines, run them through thousands
of possible futures, and read the results like an engineer.

You will use **RAPTOR Studio**, a free, open program for building
reliability block diagrams and simulating them.

The book has twenty-three short chapters, from this welcome to the
last capstone. Each chapter adds
exactly one new idea. Each chapter has a small, complete example you
build or open yourself. The examples are everyday objects: a camping
lantern, an espresso machine, a delivery drone, a toaster, a soda
vending machine — building up to a data centre engineered to a
reliability target.

=== How to use this book

. Read the story at the start of a chapter. It sets up one problem.
. Build the model in RAPTOR Studio, or open the ready-made `.rbds` file
   from the `models` folder.
. Run the simulation. Compare your numbers with the book's numbers.
. Answer the *Check yourself* questions, then open the *Answers* box
   below them to mark yourself.
. Do the exercise. It is small, and it stretches the idea one step. Its
   *Answer* box sits right underneath it — no peeking until you have run
   the thing.
. Read the *Limits of this model* box. Every chapter's example is
   built to teach one idea clearly, which means it deliberately leaves
   something out. Knowing what is missing is as much a part of
   reliability engineering as knowing what is there.

TIP: Every control on every ribbon tab and dialog is documented in the
*xref:../docs/manual.html[Reference Manual]*. Every formula this book
quotes — availability, MTBDE, SEM, the lot — is collected on one page
in the *xref:../docs/formulas.html[Formulas quick reference]*. Press
kbd:[F1] in the app to jump to the manual section for whatever panel
you are using.

[NOTE]
====
Your simulation numbers will not match the book digit for digit. The
engine rolls dice. Different dice rolls give slightly different answers.
<<ch-trials>> explains how close is close enough.
====

Start RAPTOR Studio. It opens on the start page: a blank model and some
of this guide's example models to begin from, the files you used
recently, and this guide one click away.

image::start-page.png[The start page: New (a blank model and examples), Recent and Learn]

Pick **Blank model**, an example, or a recent file — or press Esc for an
empty workbench. The workbench is a ribbon with tabs, a canvas in the
middle, and dockable panels around it:

image::app-first-look.png[The RAPTOR Studio main window]

* **Model Explorer** (left): a list of every part of your model.
* **Canvas** (centre): your diagram. You draw here.
* **Inspector** (right): details of whatever you select.
* **Data Tables** (bottom): a spreadsheet-like view of all blocks,
  nodes, and events. Fast for typing many numbers.
* **Results** (bottom): appears after you run a simulation.
* **Run** (bottom, a tab beside Results): trials, run length, analyses and
  recording for the next run.

The blue **File** button, left of the tabs, brings the start page back:
New (a blank model, or any example as a new, unsaved copy), a searchable
list of your recent files, Open, Save, Save As and Close, and a *Print

Save Bitmap, Copy View). Press Esc to go back to the model.

The *New* page offers a blank model and every example: the *Basics*,
one idea each from this guide, and the *Advanced* ones — a hospital's
emergency power, a water-treatment works, a data centre and a phased
flight — larger systems that use several features at once, with a Rates

=== The one big idea

Reliability simulation answers one question:

> *If I run this machine for this long, how often does it still work at
> the end — and how often does it work along the way?*

To answer it, the simulator needs three things:

. **Parts** that can fail — called *blocks*.
. **Rules for how the parts connect** — called the *diagram*.
. **Rules for how parts fail and get fixed** — *distributions*.

That is all. The next chapter starts with one part and one rule.

=== Annotating your diagram

The Model ribbon has an *Annotate* group with Text, Rectangle, Ellipse
and Arrow tools; their stacking order is on the Arrange ribbon. Click the canvas to place; drag to move; use the
corner handle to resize shapes. Right-click an annotation for
*Colours & Font* (border, fill, text colour and font family/size/
bold/italic). Delete with the Del key as usual.

Annotations are saved in the native `.rbds` format. The older
`.rbd` format cannot store them — RAPTOR Studio warns before
dropping them if you save as `.rbd`.
